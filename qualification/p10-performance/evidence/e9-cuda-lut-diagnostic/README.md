# E9 native CUDA spectral LUT diagnostic

This predeclared comparison uses the exact retained `c1e2cac` CUDA CLI as control and the isolated `a919045` CUDA CLI as candidate. The source comparison identifies one registration implementation change in `spectral.rs` and its corresponding reviewed assurance digest. Both Cargo locks and the native CUDA build profile match. The independent C1 CPU and physical CUDA receipts confirm the same geometry on the exact nine original E9 inputs. They bind the expected genuine `337×510` RGB16 output and the CUDA arm’s encoded and decoded hashes. No reference application is scheduled. [LUT host build and regression evidence](../e9-lut-75c-host/README.md) · [Physical C1 CUDA performance and output](../integrated-e9-corrected-cuda-c1e2cac/README.md)

Each binary gets two completed warmups in a fresh process with its own persistent case-local compiler and application cache directories. Four measured pairs follow, with stock first in pairs 1 and 3 and LUT first in pairs 2 and 4. Every launch uses the same frozen E9 flags and the same `0–31` CPU mask, CUDA 12.5 on the same physical RTX 3090 at PCI `0000:01:00.0`, and explicit GPU selection. The parent clock starts immediately before process creation and stops on the blocking `wait4` return after process exit. RGB16 validation, registration map verification and cache inventory execute outside that interval. The collector retains each result before a stop on any invalid job. A valid but slower candidate remains a measured result.

All jobs must complete without fallback, verify the actual NVIDIA device and nine exact first-reference and sequential registration maps, and reproduce the exact native C1 TIFF and decoded pixel hashes. Report both arm medians and all four paired differences. The units from `wait4` describe process resource usage only. This diagnostic supplies no P10 speed, memory or release credit. It does not rerun the ChimpStackr comparison.

The test suite uses CPU-only controls to prove order, blocking completion and failure retention, and physical-event, shape and map validation. The no-device preflight checks actual source and binary identities, native link receipt and runtime libraries, exact input hashes and the frozen schedule. Run the diagnostic only after all competing compiler and device processes have stopped and the exclusive window has been authorized. The shell watchdog limits total elapsed time to 120 seconds.
